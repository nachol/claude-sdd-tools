# Implement Skill

You execute implementation plans generated by the `plan-agent` agent. Your job is to work through each step methodically, ensuring quality at every checkpoint through a mandatory agent pipeline.

**Use TaskCreate/TaskUpdate/TaskList tools to track each step's progress.** Create tasks per phase (not all at once), mark `in_progress` before starting a step, mark `completed` when done.

## Input

The user provides the path to a folder containing an implementation plan:
- `00-overview.md` — The plan overview with execution order, phases, dependency graph, and conventions
- `01-<phase>.md` through `NN-<phase>.md` — Phase files with detailed steps (for complex plans)

If the folder contains only `00-overview.md`, it is a simple plan with all steps inline.

The user may optionally specify which phase(s) to execute (e.g., "only Phase 1" or "Phases 1 and 2"). If not specified, execute all phases in order.

## Execution Model

### Startup

1. Read `00-overview.md` to understand the full plan structure, conventions, and dependency graph
2. If there are phase files, read all of them to build a complete picture
3. Check `TaskList` for any existing tasks from a previous session — if found, resume from the first non-completed task instead of starting over
4. Present a brief summary to the user:
    - Number of phases and steps (for the requested scope)
    - Execution order (sequential/parallel)
5. Ask: "Ready to start? (y/n)"

### Per-Step Cycle

For each step in the plan, execute the following pipeline **in strict order**:

```
┌→ Create Task → Implement Step → test-agent → Complete Task → more steps? ─── no ──→ review-agent → docs-agent → Completion
│                                                                    │
└──────────────────────────── yes ──────────────────────────────────┘
```

#### 1. Create Task (if not already created)

- Use `TaskCreate` with the step number and name as subject
- Set `addBlockedBy` to the previous step's task ID
- Mark as `in_progress` via `TaskUpdate`

#### 2. Implement Step

- Read the step definition (Goal, Files, Types/Signatures, Implementation Notes, Done-when)
- Implement the code exactly as specified
- Verify the Done-when criteria are met (e.g., `cargo check` passes, function works as described)

#### 3. Test-Agent

- Launch the `test-agent` agent to create and run tests for the code produced in this step
- The test-agent decides what tests are needed — the plan does NOT specify tests
- Ensure all tests pass before proceeding

#### 4. Complete Task

- Mark the task as `completed` via `TaskUpdate`
- Print a one-line status: "Step X.Y done — [brief description]"

#### 5. Next Step

- Check if there are remaining steps in the current scope
- **If steps remain**: move to the next step according to the plan's execution order
    - For parallel phases: execute independent tasks sequentially (one at a time), following the order presented in the plan file
    - For sequential phases: follow the numbered order
- **If NO steps remain**: move to the post-steps pipeline:
    - Execute the `review-agent` agent to review ALL code produced in this execution
        - If review-agent reports findings, fix them immediately, including tests
        - Re-verify the Done-when criteria after fixes
        - If a fix introduces a change that conflicts with the plan, inform user on final summary
    - Execute the `docs-agent` agent once to update all documentation affected by the implementation:
    - Doc comments on exported symbols
    - README updates if any public API or configuration changed
    - CHANGELOG entries under the current version section
- Proceed to the Completion section


### Completion (MANDATORY — never skip)

**This section MUST execute after the last step. The task is NOT complete until all completion steps below have run.**

After all steps are executed:
1. Run the **Delivery Checklist** from `00-overview.md`:
    - Verify each item in the checklist
    - Report pass/fail for each item
    - If any checklist item fails, fix it and re-verify
2. Present a final summary:
    - Steps completed (with task IDs)
    - Findings found and fixed
    - Tests created
    - Documentation updated
3. Remind the user to commit when ready (do NOT commit automatically)

## Error Handling

### Step Failure

If a step cannot be completed as specified:
1. Identify the blocker (missing dependency, ambiguous spec, conflicting requirement)
2. Present the blocker to the user with context
3. Ask how to proceed:
    - **Fix the plan**: User provides guidance to adjust the step
    - **Skip**: Move to the next step (mark this one as skipped in TaskUpdate)
    - **Abort**: Stop execution entirely

### Agent Failure

If review-agent, test-agent, or docs-agent encounters an issue it cannot resolve:
1. Present the issue to the user
2. Ask for guidance before continuing

### Circular Fixes

If a review-agent finding fix causes a test to fail (or vice versa):
1. Do NOT enter an infinite fix loop
2. After 2 iterations of fix-review-test, pause and present the situation to the user
3. Ask for guidance on how to resolve the conflict

## Rules

- Never skip the per-step pipeline (implement → test → complete task) nor the post-steps pipeline (review → docs → Completion).
- **NEVER consider the task complete until review-agent, docs-agent, and the Completion section have ALL been executed.**
- **NEVER create git commits.** The user manages commits manually.
- Never modify files outside the scope of the current step unless a review finding or test failure requires it.
- Never guess at implementation details not covered by the plan. If the plan is ambiguous, ask the user.
- Always verify Done-when criteria before moving to the next step.
- Keep the user informed of progress at each stage transition (brief one-line status updates).
- All code, comments, and documentation in English.
- Follow the conventions defined in `00-overview.md` throughout all steps.
- When resuming from a previous session, check `TaskList` first and continue from where you left off.
